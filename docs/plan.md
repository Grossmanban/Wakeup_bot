# План реализации

Этапы — по разделу 22 ТЗ ([tz.md](tz.md)). Модуль считается готовым, когда работают
серверная логика, права, история и тесты, а не только интерфейс.

## Аудит репозитория (этап 1)

На 27.10.2026 репозиторий `Grossmanban/Wakeup_bot` был пустым: ни одного коммита.
Готовых модулей, конфликтов со старым кодом и данных для миграции нет. Проект
делается с нуля.

## Что сделано на этапе 2

- Проверка Telegram initData на сервере (HMAC, срок действия, защита от повторных полей).
  Telegram ID берётся только из подписи.
- Один Telegram ID — один профиль (уникальный индекс и upsert, проверено конкурентным тестом).
- Регистрация: ФИО → заявка → уведомление рассматривающим → одобрение или отказ с причиной.
  Отклонённый может подать заявку снова. Пока заявка не рассмотрена, её можно исправить.
- Смена ФИО через заявку; старое и новое значения сохраняются в заявке и в аудите.
- Роли: владелец, администратор, тренер, инструктор, сотрудник. Права выдаются отдельно от роли
  ([permissions.md](permissions.md)). Администратор по умолчанию прав не имеет.
- Разделены состояние аккаунта (активен / отключён / заблокирован) и доступ к Mini App.
  Тексты для отключённого и заблокированного — дословно из ТЗ.
- Оргструктура: сети, руководство «тренер → инструктор → сотрудник». Команды могут
  пересекаться, человек в них не дублируется.
- Журнал аудита: только добавление, UPDATE и DELETE запрещены триггером БД.
- Очередь Telegram-сообщений: запись в той же транзакции, что и изменение данных,
  повторы с паузами, защита от дублей, окончательные ошибки пишутся в аудит.
- Mini App: регистрация, экраны статусов, профиль, заявки, сотрудники с фильтрами,
  карточка сотрудника (роль, статус, доступ, разрешения, сети, команда, история), сети,
  тема (как в Telegram / светлая / тёмная).
- 30 автотестов backend; сценарий в браузере проверен вручную через Playwright.

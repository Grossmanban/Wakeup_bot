# План реализации

Этапы — по разделу 22 ТЗ ([tz.md](tz.md)). Модуль считается готовым, когда работают
серверная логика, права, история и тесты, а не только интерфейс.

## Аудит репозитория (этап 1)

На 27.10.2026 репозиторий `Grossmanban/Wakeup_bot` был пустым: ни одного коммита.
Готовых модулей, конфликтов со старым кодом и данных для миграции нет. Проект
делается с нуля.

## Что сделано на этапе 2

- Проверка Telegram initData на сервере (HMAC, срок действия, защита от повторных полей).
  Telegram ID берётся только из подписи.
- Один Telegram ID — один профиль (уникальный индекс и upsert, проверено конкурентным тестом).
- Регистрация: ФИО → заявка → уведомление рассматривающим → одобрение или отказ с причиной.
  Отклонённый может подать заявку снова. Пока заявка не рассмотрена, её можно исправить.
- Смена ФИО через заявку; старое и новое значения сохраняются в заявке и в аудите.
- Роли: владелец, администратор, тренер, инструктор, сотрудник. Права выдаются отдельно от роли
  ([permissions.md](permissions.md)). Администратор по умолчанию прав не имеет.
- Разделены состояние аккаунта (активен / отключён / заблокирован) и доступ к Mini App.
  Тексты для отключённого и заблокированного — дословно из ТЗ.
- Оргструктура: сети, руководство «тренер → инструктор → сотрудник». Команды могут
  пересекаться, человек в них не дублируется.
- Журнал аудита: только добавление, UPDATE и DELETE запрещены триггером БД.
- Очередь Telegram-сообщений: запись в той же транзакции, что и изменение данных,
  повторы с паузами, защита от дублей, окончательные ошибки пишутся в аудит.
- Mini App: регистрация, экраны статусов, профиль, заявки, сотрудники с фильтрами,
  карточка сотрудника (роль, статус, доступ, разрешения, сети, команда, история), сети,
  тема (как в Telegram / светлая / тёмная).
- 30 автотестов backend; сценарий в браузере проверен вручную через Playwright.

## Что сделано на этапах 3–5

- Продукты: все настройки из ТЗ 4 (этапы, чек-листы, таймеры, фото, OCR, причины ошибок,
  обязательные поля, ограничение по полу, стажировка), статусы активен/скрыт/архив/удалён.
- Типы заданий с названиями из Excel и числом единиц за задание.
- Ставки: история изменений; приоритет индивидуальная → ставка роли; без ставки задание не
  выдаётся и не допускается к оплате (ошибка конфигурации, а не ноль).
- Продуктовые доступы выдаёт только владелец; продукт можно ограничить сетями.
- Импорт .xlsx: предпросмотр с ошибками по строкам, дубликаты в файле и в базе, пустые строки,
  дополнительные колонки; подтверждение идемпотентно, повторная загрузка не создаёт дублей.
- Выдача из пула атомарна (SKIP LOCKED + блокировка сотрудника): два человека не получают одно
  задание, лимит не превышается параллельными запросами; ключ идемпотентности от двойного нажатия.
- Выполнение: ссылка → «Найдено» → этапы с чек-листами и серверными таймерами → фото →
  финальное фото → завершение. Сброс таймера с причиной, сообщение об ошибке с причиной из списка.
  Каждый шаг пишется в историю задания с серверным временем.
- Камера Mini App с предпросмотром, «Отправить / Переснять / Отмена»; фото на диске сервера,
  «загружено» — только после ответа сервера.
- OCR (PaddleOCR) с правилами «содержит / совпадает / похожесть», 3 попытки по умолчанию,
  неудачные фото сохраняются, после исчерпания — ручная проверка с уведомлением.
- Ручная проверка: одобрить / вернуть сотруднику / отменить, с историей попыток.
- Модерация: допустить / отклонить с причиной / вернуть на исправление; решение можно
  изменить, деньги корректируются сторно. Модератор не проверяет свои задания.
- Качество = одобренные / (одобренные + отклонённые) единицы; ожидающие модерации не входят.
- Допуск к оплате сразу создаёт запись заработка в финансовом журнале по ставке на момент решения.

## Что сделано на этапе 6

- График на текущую и следующую неделю: «Встать в график» с подтверждением (дата, время, точка,
  план по продуктам, прогноз заработка по действующим ставкам), выходной, отмена.
- Сроки: время и точка — до 00:00 дня смены, план — до 22:00 предыдущего дня (по МСК, на
  сервере). Руководитель с правом «Управление графиком» может менять и позже.
- Смена на сегодня, поставленная сотрудником, ждёт подтверждения руководителя; до этого она
  не считается подтверждённой и не занимает место в точке.
- Вместимость точки проверяется по пересекающимся по времени подтверждённым сменам под
  блокировкой точки — параллельные запросы не займут одно место вдвоём.
- Минимум смен в неделю (1–7) — настройка владельца; на экране видно выполнение.
- Статусы дня: подтверждённая смена, работает сегодня, работал (есть выполненные единицы),
  смена без выполненных заданий, выходной, ожидает подтверждения, статус не указан.
- Сводка по дням с фильтрами (период, сеть, тренер, инструктор, сотрудник, продукт): план,
  факт, процент выполнения, итоги.
- «Распред» по точкам с планом и фактом, кнопка «Скопировать распред».
- Видимость графика коллег: только свой (по умолчанию) / занятость / подробно.

## Что сделано на этапе 7

- Финансовый журнал: заработок, отмена заработка, штрафы, бонусы и их отмена, реферальные
  бонусы, корректировки, взаимозачёты, сниженная ставка. Записи не изменяются; у каждой —
  автор, причина, исходная операция, связь с выплатой и ключ идемпотентности.
- Штрафы в рублях и в единицах (по ставке продукта на момент штрафа).
- Удержания: долги гасятся из выплат частями, старые первыми, выплата не бывает отрицательной,
  один долг не списывается дважды (таблица погашений).
- Ручные бонусы и автоматические правила (минимумы по продуктам, качество, период),
  начисление один раз, уведомление сотруднику.
- «Налог на лень»: ежедневное закрытие дня фиксирует недобор; при выплате эти единицы
  оплачиваются первыми по сниженной ставке, остаток переносится; персональные исключения.
- Выплата: предпросмотр (единицы, ставки, заработок, бонусы, штрафы, удержания, остаток долга,
  единицы по сниженной и обычной ставке, итог) → подтверждение с неизменяемым снимком.
  Повторное нажатие не создаёт вторую выплату; если данные изменились после предпросмотра,
  подтверждение отклоняется. Задания выплаты получают статус «Оплачено».
- Фоновые задачи по расписанию с защитой от повторного запуска.

# Модель данных

Источник истины — PostgreSQL. Время хранится в `timestamptz` (UTC), даты бизнес-логики
считаются по Europe/Moscow (`backend/app/timeutil.py`). Схема меняется только миграциями
Alembic (`backend/migrations`).

## Люди, доступ, аудит

| Таблица | Назначение | Важные ограничения |
|---|---|---|
| `users` | Профиль: Telegram ID, username, ФИО из Telegram и подтверждённое ФИО, роль, состояние, доступ к Mini App, может ли бот писать первым | `telegram_id` уникален |
| `registration_requests` | Заявки на регистрацию с решением, автором решения и причиной | не больше одной открытой заявки на человека (частичный уникальный индекс) |
| `name_change_requests` | Заявки на смену ФИО: старое и новое значения | не больше одной открытой заявки на человека |
| `user_permissions` | Выданные разрешения; `network_id = NULL` — на все сети | уникальность (человек, разрешение, сеть), NULL считается одним значением |
| `networks` | Сети | название уникально; архив вместо удаления |
| `user_networks` | Принадлежность людей к сетям (несколько сетей на человека) | |
| `supervisions` | Рёбра иерархии «руководитель → подчинённый» | нельзя руководить собой |
| `audit_events` | Журнал аудита: категория, действие, инициатор, объект, старое и новое значения, причина, результат | UPDATE и DELETE запрещены триггером |
| `telegram_outbox` | Очередь исходящих сообщений Telegram | `dedup_key` уникален — повтор операции не шлёт второе сообщение |

Категории аудита совпадают с темами Telegram-архива из ТЗ 14: `users`, `penalties`,
`bonuses`, `tasks`, `photos`, `schedule`, `finance`, `settings`, `groups`, `system`.

## Принципы

- Деньги — целые копейки (`BIGINT`), никаких float.
- Финансовые операции не изменяются: исправление — новая запись со ссылкой на исходную.
- Идемпотентность через уникальные ключи (импорт заданий, начисления, выплаты, сообщения).
- Конкурентные операции (выдача задания, вместимость точки, выплата) — блокировки строк
  или атомарный UPDATE с условием.

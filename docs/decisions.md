# Решения и значения по умолчанию

ТЗ (раздел 23) требует не принимать критичные решения молча. Здесь записано, что выбрано,
почему и где это поменять. Пункты с пометкой **нужно согласовать** ждут ответа заказчика.

## Решения заказчика (27.10.2026)

- Стек: Python (FastAPI, aiogram), PostgreSQL, React Mini App.
- Хостинг: собственный сервер.
- OCR: бесплатный, лучший по качеству → PaddleOCR (Apache 2.0). Движок подключается через
  интерфейс и заменяется без переделки остального кода.
- Фото хранятся на диске сервера.

## Правила этапов 3–5

- **Ставка** фиксируется в момент допуска задания к оплате. Изменение ставки позже не меняет
  уже начисленное.
- **Лимит активных заданий** считает только задания в статусе «Активное» по этому продукту.
- **Сообщение об ошибке** приостанавливает задание («ожидает ручного решения») и уведомляет
  тех, у кого есть право ручной проверки.
- **OCR**: если у задания и продукта нет ожидаемого текста, автоматическая проверка невозможна —
  задание уходит на ручную проверку с причиной. Техническая ошибка распознавания не тратит
  попытку. Регистр, «ё/е», пробелы, знаки препинания и похожие латинские буквы (A/А, K/К…)
  не учитываются.
- **Ручное одобрение** после OCR отправляет задание на модерацию; если этапы ещё не пройдены —
  возвращает его сотруднику для продолжения.
- **Возврат на исправление** даёт новые попытки OCR; задание снова проходит финальный шаг.
- **Изменение решения модерации** (одобренное → отклонено, в том числе после выплаты) не
  удаляет начисление, а добавляет сторно; если деньги уже выплачены, сторно становится долгом
  и удерживается из следующих выплат.
- **Модератор** не может проверять собственные задания (кроме владельца).

## Правила этапа 6

- Сотрудник встаёт в график на текущую и следующую неделю (ТЗ 9). Будущая смена после
  подтверждения в диалоге сразу становится подтверждённой; смена на сегодня ждёт руководителя.
- Ожидающая заявка место в точке не занимает (раздел 23, значение по умолчанию).
- Смена не переходит через полночь: окончание должно быть позже начала в тот же день.
- Одна действующая смена на человека в день.
- «Фактически работал» — есть хотя бы одна выполненная единица (задание завершено в этот день
  по МСК), независимо от того, была ли смена. Подтверждённая смена без выполненных заданий
  показывается отдельно.
- Коллеги для просмотра графика — люди из тех же сетей (или все, если сотрудник не в сети).

## OCR

PaddleOCR 3.x, модели `PP-OCRv5_mobile_det` + `eslav_PP-OCRv5_mobile_rec` (кириллица),
`enable_mkldnn=False` (в Paddle 3.x oneDNN падает на этих моделях). Проверено на тестовом
изображении: «Спасибо за отзыв! / Код заказа: Янд-4821» распознаётся верно, ~1 с на CPU.
Модели (~20 МБ) скачиваются при первом распознавании и хранятся в томе `ocr_models`.
`OCR_ENGINE=none` отключает автоматическую проверку — такие фото уходят на ручную проверку.

## Правила этапа 2

- Отклонённый кандидат может подать новую заявку. Старая остаётся в истории.
- Заявку на регистрацию можно исправить, пока она не рассмотрена. Изменение пишется в аудит.
- Пока регистрация не одобрена, все рабочие разделы закрыты (ответ 403 `not_registered`).
- Своё ФИО владелец меняет сам, без заявки: подтверждать некому.
- Статус администратора меняет только владелец, даже если у другого админа есть `users.status`.
- Свой статус менять нельзя.
- Чужой для пользователя сотрудник возвращает 404, а не 403, чтобы нельзя было перебором
  узнать существующие ID.
- Пока нет продуктов (этап 3), у всех, кроме владельца, на экране показано
  «Вам пока не выданы доступы к продуктам». Это реальное состояние, а не заглушка.

## Ограничения Telegram

- **Бот не может написать первым** тому, кто ни разу не нажимал /start в боте или заблокировал
  его. Такая отправка завершается окончательной ошибкой, она видна в аудите, а в карточке
  сотрудника показано «Не запускал бота или заблокировал его». Для приглашений (этап 10)
  оператор получит ссылку, чтобы передать её вручную.
- **Статус «Отправлено»** означает только, что Telegram API подтвердил отправку, а не что
  сообщение прочитано.
- **Список участников группы** Bot API не отдаёт. Членство проверяется по Telegram ID
  (`getChatMember`, бот должен быть администратором группы) и по событиям изменения
  участников. Если проверить не удалось, показывается «Не удалось проверить».
- **Камера в Mini App** — только браузерная (`getUserMedia` / `<input capture>`). Нативной
  камеры Telegram для Mini App не даёт; на части Android-клиентов возможны сбои.
- **initData** действительны сутки (`INIT_DATA_MAX_AGE`). После этого приложение нужно
  открыть заново.

# Безопасность и целостность данных

## Вход

- Mini App передаёт `initData` в заголовке `Authorization: tma <initData>`. Сервер проверяет
  HMAC-подпись токеном бота и срок действия (`INIT_DATA_MAX_AGE`). Telegram ID берётся только
  из подписанных данных, параметры запроса и тело для этого не используются.
- Вне Telegram вход невозможен. Владелец назначается только через `OWNER_TELEGRAM_IDS`.
- Токен бота не пишется в логи и не отдаётся клиенту.

## Права

- Каждый маршрут API проверяет разрешение и область видимости на сервере
  (`app/services/access.py`). Скрытие кнопок в интерфейсе — только удобство.
- Чужой объект возвращает 404, а не 403, чтобы ID нельзя было перебрать.
- Отключённый, заблокированный или без доступа к Mini App аккаунт получает 403; бот
  игнорирует его кнопки и ответы.
- Модератор не может проверять свои задания; финансовые, кадровые и графиковые действия
  нельзя выполнять над собой; правила, действующие на всех, требуют права на «все сети»
  (подробно — permissions.md, «Ограничения»).
- Фото засчитываются только для текущей попытки текущего исполнителя: после возврата в пул
  или на исправление старые фото не принимаются как доказательство. Попытки OCR резервируются
  при загрузке, поэтому параллельные загрузки не дают лишних попыток.
- Повтор запроса «Взять задание» возвращает задание, только пока оно за этим сотрудником.

## Целостность

- Деньги — целые копейки. Записи журнала не изменяются; исправление — новая запись.
- Выплата — неизменяемый снимок с ключом идемпотентности, считается под блокировкой строки
  сотрудника; если данные изменились после предпросмотра, подтверждение отклоняется.
- Выдача задания — `FOR UPDATE SKIP LOCKED`; вместимость точки — блокировка строки точки;
  повторные запросы — `Idempotency-Key`.
- Журнал аудита — только добавление (UPDATE и DELETE запрещены триггером БД).
- Сообщения Telegram идут через очередь с уникальным `dedup_key`; фоновые задачи отмечаются
  в `job_runs`, поэтому повторный запуск не дублирует сообщения и начисления.

## Файлы

- Фото принимаются только JPEG/PNG/WebP, тип проверяется по содержимому, размер ограничен.
  Файл сохраняется под случайным именем вне каталога статики и отдаётся только через API с
  проверкой прав.
- Выгрузки отдаются по одноразовой ссылке, которая живёт 10 минут и выдаётся только тому, у
  кого есть право `export`.
- Текст рассылок очищается: допускаются только безопасные теги Telegram-HTML. Шаблоны и
  данные пользователей в сообщениях бота экранируются.

## Проверка

На этапе 13 проведён отдельный разбор кода на обход прав и целостность финансов. Найденные
проблемы исправлены, на каждую есть регрессионный тест в `backend/tests/test_security.py`
(тесты падают на прежнем коде).

## Сеть

- Caddy выдаёт HTTPS, включает HSTS и Content-Security-Policy: скрипты только с своего домена и
  telegram.org, встраивание только в клиенты Telegram.
- БД не публикуется наружу, доступна только контейнерам `api` и `bot`.
- CORS выключен: Mini App и API работают на одном домене.

## Эксплуатация

- `deploy/backup.sh` каждый день сохраняет дамп БД и фото, копии старше 14 дней удаляются.
- Ошибки Telegram не теряют данные: фото и сообщения остаются в очереди с повторами и видны в
  разделе фотоотчётов.

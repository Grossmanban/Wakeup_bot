## Алгоритм /start

Проверки на сервере, по порядку:

1. **В системе** — владелец из `OWNER_TELEGRAM_IDS`, аккаунт в любом статусе кроме «не
   зарегистрирован», или анкета кандидата в работе → обычный ответ. Если такой человек открыл
   приглашение — «Вы уже зарегистрированы»: приглашение не тратится, роли не меняются,
   дубликат не создаётся.
2. **`inv_<токен>`** — ищется запись приглашения по токену под блокировкой строки. Подходит
   только действующее: не отозвано, срок не истёк, использований меньше лимита. Запоминается,
   что этот Telegram ID открыл приглашение (claim), бот присылает кнопку приложения.
3. **`ref_<код>`** — код принадлежит активному пользователю с правом `referrals.use` (или
   владельцу) → приветствие и анкета кандидата, обычные этапы отбора и обучения.
4. **Ранее полученное разрешение** — повторный /start без параметра у того, кто уже открыл
   действующее приглашение или перешёл по действительной реферальной ссылке.
5. **Иначе** — бот молчит, событие пишется в журнал.

Тип приглашения определяется записью в базе, а не текстом ссылки: `ref_` с токеном
приглашения или изменённый токен — молчание. Токен — `secrets.token_urlsafe(24)` (192 бита).
В журнал токен не записывается (источник — `inv_…`).

## Регистрация по приглашению

`POST /staff-registration` (только фамилия и имя):

- нужен claim этого Telegram ID на действующее приглашение — проверяется под блокировкой
  приглашения, поэтому одноразовой ссылкой может воспользоваться только один человек;
- аккаунт становится активным с ролью «Сотрудник»: без анкеты, отбора и обучения; приглашение
  не даёт прав выше сотрудника;
- счётчик использований увеличивается, claim отмечается использованным; открытая заявка на
  регистрацию, если была, закрывается; пригласившему приходит сообщение;
- уже активный аккаунт не меняется.

Проверка доступа выполняется не только при /start: экран Mini App, `POST /registration`,
анкета кандидата и регистрация по приглашению проверяют права на сервере, рабочие разделы
закрыты для неактивных аккаунтов, кнопки и ответы в боте от посторонних не обрабатываются.

## Журнал попыток доступа

Одна запись на Telegram ID (`access_attempts`): username, имя и фамилия из Telegram, первое и
последнее обращение, число попыток, источник (параметр ссылки). История — `access_events`:
/start, сообщения (текст до 500 символов), нажатия кнопок, открытие приложения напрямую (не
чаще раза в 10 минут), открытие и использование приглашения, переход по реферальной ссылке.
Статус вычисляется по текущим данным: «Нет приглашения», «Доступ разрешён», «На
рассмотрении», «Зарегистрирован», «Отключён», «Заблокирован».

Бот видит только то, что передаёт Telegram: ID, имя, username, параметр /start, текст
сообщений. Телефон и прочее недоступны.

## Что сделать в Telegram

- В @BotFather → Bot Settings → Configure Mini App выключить главное мини-приложение: иначе
  кнопка «Открыть» видна в профиле бота всем (внутри посторонний увидит только «Доступ по
  приглашению»).
- После обновления всем, кто уже работает, достаточно нажать /start — кнопка меню вернётся в
  их чате.

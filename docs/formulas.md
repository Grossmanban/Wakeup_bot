# Формулы и правила расчёта

Все даты бизнес-логики — по Europe/Moscow. Деньги — целые копейки.

## Качество (ТЗ 8.1)

```
Качество = одобренные единицы / (одобренные + отклонённые единицы) × 100%
```

- «Одобренные» — статусы «Допущено к оплате» и «Оплачено».
- Ожидающие модерации не входят ни в числитель, ни в знаменатель.
- Нет решений — показывается «—».
- Рядом всегда размер выборки («Качество 80%, 40 проверенных единиц»). Если проверенных единиц
  меньше порога продукта (по умолчанию 20), показывается предупреждение «малая выборка».

## Время и производительность (ТЗ 16.3, 16.4)

- **Время выполнения задания** — от нажатия «Найдено» до завершения, по серверному времени.
- **Зафиксированное время сотрудника** — объединение интервалов его заданий. Пересекающиеся
  задания не суммируются: 10:00–11:00 и 10:30–11:30 дают 1,5 часа, а не 2.
- **Часы смен** показываются отдельно и в производительности не используются: плановая смена
  не доказывает работу.
- Если зафиксированного времени меньше 15 минут, показатели в час не считаются —
  «Недостаточно данных».

```
Валовые единицы в час = выполненные единицы / зафиксированное время
Фактические оплачиваемые единицы в час = допущенные к оплате единицы / время выполнения этих заданий
Прогноз оплачиваемых единиц в час = валовые единицы в час × (качество / 100)
Заработок в час = заработок по допущенным заданиям / время их выполнения
```

Примеры: 10 ед./ч при качестве 50% → 5 оплачиваемых ед./ч; 8 ед./ч при 95% → 7,6.

**Почасовое распределение:** единица относится к часу завершения задания (МСК).

## Ставки (ТЗ 11.2)

1. Индивидуальная ставка сотрудника по продукту.
2. Ставка роли по продукту.
3. Иначе — ошибка «Не настроена ставка»: задание не выдаётся и не допускается к оплате.

Ставка фиксируется в записи журнала в момент допуска к оплате.

## Финансовый журнал (ТЗ 11)

| Запись | Знак | Когда |
|---|---|---|
| Заработок | + | допуск задания к оплате: единицы × ставка |
| Отмена заработка | − | решение модерации изменено с «допущено» на «отклонено» |
| Штраф | − | вручную, в рублях или в единицах × ставка продукта на момент штрафа |
| Бонус | + | вручную или по автоматическому правилу |
| Отмена бонуса | − | вручную или при снижении подтверждённого объёма обучения (реферальный) |
| Реферальный бонус | + | завершение обучения приглашённого |
| Корректировка, взаимозачёт | ± | вручную, с причиной |
| Сниженная ставка | − | при выплате, за накопленные единицы «налога на лень» |

Записи не изменяются и не удаляются; исправление — новая запись со ссылкой на исходную.

## Выплата (ТЗ 11.3, 11.6)

```
Начислено = невыплаченные положительные записи с датой в периоде
Сниженная ставка = Σ по накопленным единицам: единицы × (обычная ставка − сниженная)
Доступно = Начислено − Сниженная ставка
Удержано = min(непогашенные долги на конец периода, Доступно), старые долги первыми
К выплате = Доступно − Удержано  (≥ 0)
Остаток долга = долги − Удержано
```

- Долг — непогашенная часть отрицательной записи. Погашения записываются отдельно, поэтому
  один долг не списывается дважды.
- Подтверждение сохраняет неизменяемый снимок расчёта. Если данные изменились после
  предпросмотра, подтверждение отклоняется.
- Задания, чьи начисления вошли в выплату, получают статус «Оплачено».

## «Налог на лень» (ТЗ 11.5)

Трактовка подтверждена заказчиком:

```
Недобор дня = max(0, минимальный дневной объём − выполнено за день)
```

- Считается за день, когда сотрудник работал по продукту: была подтверждённая смена с планом
  по нему или выполнена хотя бы одна единица.
- Недобор копится как «единицы по сниженной ставке» отдельно от штрафов и долгов.
- При выплате столько же единиц из выплаты (самые ранние) оплачиваются по сниженной ставке
  вместо обычной; остаток переносится на следующие выплаты.
- Персональное исключение отключает правило для сотрудника.

Пример: минимум 5, выполнено 2 → 3 единицы. В выплате 4 единицы по 50 ₽, сниженная ставка 20 ₽
→ 3 × 20 + 1 × 50 = 110 ₽.

## Автоматический бонус (ТЗ 11.4)

Начисляется один раз на сотрудника и правило, когда за период правила по каждому продукту
набран минимум допущенных к оплате единиц и качество по этим продуктам не ниже порога.

## Новичок (ТЗ 15.3)

Рабочий день — календарный день МСК, в который выполнена хотя бы одна единица (несколько
заданий — один день). Третий такой день — дата перехода в действующие сотрудники.

## Цели и соревнования (ТЗ 10)

- Учитываются единицы по дате выполнения задания. Режим задаётся в цели: все выполненные
  единицы продукта, допущенные к оплате или только оплаченные (вошедшие в подтверждённую выплату).
- Гонка до порога: место — по времени достижения порога. Максимум за период: по объёму, при
  равенстве — кто раньше достиг итогового результата (или общее место).
- Командные показатели: общий объём, средний на участника, минимум каждого участника.
